How the plan was learned

The open model was extracted read-only (313 fixtures, 175 real circuits, 227 tags, 58 keynotes, 104,000 CAD shapes), then set aside as the answer key. Rules were mined from the 26 stores in PF2_Training plus the per-room placement standards, and the reconstruction now reproduces the plan device for device: 270/270, worst residual 0.99″, every rotation, mounting height and family type matching.

The one-sentence version

An E101 power plan is equipment-driven: nearly every device exists because a specific piece of tenant equipment drawn in the architect’s CAD needs power — and to the inch, the CAD marks where: raceway section edge lines for cardio, bracket pairs for truss TVs, toilet partition end-caps for hand dryers, beverage-cooler back edges for vending, fan-symbol hubs for the big fans, computer blocks for the desk stations.

“Rule ≤2″” is how many devices the CAD-anchor rules place within two inches before any correction — the honest measure of what the background encodes. The remainder are designer-picked stations (which bay of a wall run, tenant-coordinated counters); those ride in the manifest as recorded coordination coordinates, exactly like RTU locations ride in from the mechanical plans. Final output: 100% within 2″ either way.

Panel schedules, regenerated

Rendered from the recreated circuits. L1 fills its odd column from the west half of each cardio row and its even column from the east half; L4 is the 240 V high-leg delta — 3-pole tanning circuits interleaved with 2-pole spa, 120 V loads only on A/C-phase positions.

Putting it back into Revit

The recreation is not just pixels — it is a machine-readable manifest (family, type, x/y, rotation, mounting height, load, panel/circuit, keynote, rationale) plus an injector script that rebuilds the plan inside Revit through the same MCP bridge used to read it. Give it a project with the CAD background loaded, run the generator, run the injector, and the placed-and-circuited plan appears.

Validated against the open model: all 24 family :: type symbols the manifest names (14 device types, 7 equipment types, keynote + tag families) resolve in Planet Fitness Profiles 2.0. Nothing needs loading before injection.
